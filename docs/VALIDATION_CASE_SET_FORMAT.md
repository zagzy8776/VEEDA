# Doctor-reviewed case-set format

A **case set** is the input to a per-feature validation harness. It pairs a known
truth (decided by a reviewing clinician) with what the system under test produced, so
the harness can compute sensitivity, specificity and an error range. VEEDA ships no
case sets — a reviewing clinician supplies them.

## Metadata (required)

Every case set carries a metadata block. The same provenance rules as content packs
apply: a reviewer **name** and credential **type** only (never a license number).

| Field | Meaning |
|-------|---------|
| `id` | Stable id, e.g. `spo2.cases`. |
| `version` | Case-set version, e.g. `1.0.0`. |
| `reviewer` | Name or role of the reviewing clinician. |
| `reviewerCredential` | Credential **type** (e.g. `Physician`) — not a number. |
| `reviewDate` | ISO date (`YYYY-MM-DD`). |
| `region` | Region the cases apply to. |
| `stratifiers` | Sub-populations covered, e.g. `["skin_tone_V", "skin_tone_VI"]`, conditions, or age bands. |

## Case format

Each case is a plain object (JSON lines or a JSON array):

```json
{ "id": "c1", "truth": true, "predicted": true, "stratum": "skin_tone_V" }
```

| Field | Meaning |
|-------|---------|
| `id` | Unique case id. |
| `truth` | The reviewer's gold-standard decision (`true`/`false`). |
| `predicted` | What the system produced (`true`/`false`), or **`null`** when it gave no result (an abstention). |
| `stratum` | Optional sub-population label matching `stratifiers`. |

## What the harness reports

`runHarness()` (in `src/app/validation.ts`) returns:

- `sensitivity` and `specificity` over the cases the system actually decided;
- `abstentionRate` — the share of cases where the system gave no result;
- `byStratum` — sensitivity/specificity per stratum, so skin-tone and condition
  sub-groups are visible rather than hidden in an average;
- `meetsAcceptance(minSensitivity, minSpecificity)` — whether the result clears the
  thresholds a deployment requires.

An **error range** (e.g. `±2%`) is supplied by the reviewer as text and stored in the
`ValidationRecord`; it is never generated by the app.

## Rules

1. A case set with no reviewer metadata is not usable.
2. Abstentions are reported, never counted as correct.
3. Bad conditions (poor light, motion, occlusion) should be included as their own
   strata so the results are honest about the hard cases.
4. A model is promoted only when its harness result meets acceptance **and** the
   release is pinned explicitly (`promotionDecision`).
